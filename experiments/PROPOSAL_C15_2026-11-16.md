## Why a new dataset is needed
- petracer_embryo has only B and C left: two E7.5 embryos, one E9.0 and one E10.0.
- The C14 effect is about 0 at E7.5-E8.0, so a B look is probably underpowered. H-c and H-d face the same limit.
- What would open the next door is a lineage + state dataset with many independent units. Many units means fresh sealed partitions and real power.

## Re-alignment (step 3)
- The goal says to *model* fate behaviour. Since chapter 6, chapters have tested claims with classifiers. A chapter that fits Cellware's mechanistic fate model, with an inherited-state term from C14-S4's programs, to lineage trees would bring the model back.
- On petracer_embryo this fails H19 power: there is no powered sealed partition left.

## Groundwork done 2026-11-17 (Bence: "go 1"; reading and metadata only, nothing downloaded)

### #25 (arXiv 2610.40447), overlap read
- It uses the same PEtracer mouse embryo atlas as C14 (E7.5-E10.0), with a tree-aware generative model ("lineage inpainting") that predicts state dynamics from relatives' states.
- It does **not** test state beyond annotated type against relatives' fate. It does **not** evaluate on held-out embryos: the only held-out split we found is 11 of 56 clone trees, two per stage from different embryos (supplement, read via a summary). It fits **no** mechanistic model (no rates, no inherited-state term).
- C14's claim is not pre-empted. #25 is the closest neighbour and belongs in WRITEUP_C14's value section.
- Exposure rule: its held-out trees may come from our sealed B/C embryos. Its per-embryo or per-clone results stay unread. Its data (Zenodo 10.5281/zenodo.23750040, 0.69 GB) is not needed.

### #12 (Cell 2022), methods read
- Recorder: an evolving Cas9 lineage recorder in a mouse in vivo growth model. Every lineage-traced cell has a paired scRNA profile. Trees are built with Cassiopeia.
- **Units:** each growth is clonal and has its own tree, so there are no cross-unit relatives. The paper counts, by arm:
  - arm 1: 35 growths (29 primary, 6 secondary), 40,386 cells
  - arm 2: 57 growths (24 primary, 33 secondary), 18,321 cells
  - arm 3: 35 growths (23 primary, 12 secondary), 13,825 cells
  - In all: about 127 growths and 76 primaries. Arm 1 averages about 1,150 cells per growth. The QC floor is 100 cells.
- **Independence:** growths in one host share the host, so a partition must be by host. Sample names look like `<number>_<arm>_T<n>`; the leading number is probably the host ID (unconfirmed). The host count is not in the text or in the SRA metadata (26 lanes, one generic sample name). It is readable only from the processed data.
- **States:** Leiden clusters on scVI, named by markers. These would take the place of cell type.
- **Authors' tree analyses:** parsimony state-transition counts ("plasticity"), state-pair phylogenetic coupling, and fitness inference. They report that **directionality of transitions could not be determined.** That is an open gap a fitted transition-rate model with an inherited-state term would address. They do not test state beyond cluster predicting relatives' cluster on held-out units.
- **Data:**
  - Processed data (expression, trees, statistics): Zenodo 10.5281/zenodo.5847461, one tarball of 1,305 MB (Zenodo API size), CC-BY-4.0, open.
  - Raw data: SRA PRJNA803321, 110 runs, about 3.3 TB. Not needed.
  - Code: github mattjones315/KPTracer-release.
