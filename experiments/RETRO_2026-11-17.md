## How C14 served the long-term goal
- C14 confirmed (on A) that a cell's state beyond its type predicts its relatives' fate in vivo.
- S4 named the state (an origin program). S5 showed it is not explained by cells sitting between types. That makes it a justified inherited-state term for a mechanistic fate model.
- C14 itself fitted no model. S5 found the dataset (#12, 32 hosts) where a fitted model can be tested on sealed hosts. That is C15's job.

## Went right
1. **Predictions were stated before the runs, and one failed in the informative direction.** S5(b) predicted MIXED and got MEMORY-CONSISTENT (retained 0.94). Both smoke tests guarded the reading.
2. **B was not spent.** A cheap local simulation from committed numbers said B is a one-embryo look (power 0.60). It stays sealed.
3. **The #12 structure was read without exposure.**
   - Size and md5 were checked against the record.
   - Output was recoded (no arm or host names).
   - No pickles were loaded and no state or result values were read.
4. **Compute discipline:** both data steps ran on Actions with run URLs. The only local run was the 9 s arithmetic.
5. **Synthetic path tests ran for all three scripts before dispatch** (practice line from RETRO_2026-11-15).

## Went wrong
1. **The rows-per-unit count from #12 is not a cell count.** The script took the table with the most unit-ID matches, which was probably an allele table (755k rows against about 72k cells in the paper). The pre-registration did not say which table counts cells.
2. **A scope-guard bug was found:** `allowed_scripts` entries carry `.py`, but the guard compares bare names, so the allow-list never matches. No wrong run followed (pre-registrations carried it). Not fixed; it needs Bence's OK to touch the guard.
3. **The S5 FOCUS reopening churned C14 again** (closed, S4, S5). It was harmless, but each reopen needs this retro.
4. **All data-lane work was again done by Opus.** The Sonnet agent is still not offered in this session, and Bence's "go" was taken as the answer.
