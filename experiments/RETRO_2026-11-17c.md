## C16 in one line
A hidden inherited P/L bias on the embryo train trees survived time, axial-identity and position controls in 6/6 embryos, and its expression trace looks like shared streak-exit history. No claim: B has one usable embryo, so the oracle refuses the look. The biology is largely published, much of it on the same data (lit/c16_novelty_2026-11-17.md). Write-up: WRITEUP_C16.md.

## How C16 served the long-term goal
- It closed the gap noted on 2026-11-16: the first mechanistic model fitted to new data since chapter 6, on whole-embryo trees.
- It gave the fate model a time structure (switching slows about 5x with depth; half-life about 10 divisions) that a morphogenesis model can reuse.
- It did not reach morphogenesis: position is inferred from expression, not measured.

## Went right
1. **Each alternative was tested in turn** (time, axial identity, within-embryo position, own fate likeness), each as its own pre-registered step, with no sealed data read.
2. **Synthetic smoke tests ran before every real-data run** and caught four thresholds that were too tight before any real number was seen.
3. **Bence's questions drove the right controls:** "isn't this the opposite of C14?" led to S1, the position question led to S3, the E8.0 jump led to S3c, and "why not test on holdout?" led to S4a.
4. **Actions with 4 processes per job** cut S1 from about 3 h to about 25 min once Bence pointed it out.
5. **The B look was stopped at the gate,** not worked around, when B turned out to hold one usable embryo.

## Went wrong
1. **The literature check came after the build, again.** The C16 map on day one flagged Colgan 2026 as likely covering timing, but whether its heritable programmes and position results pre-empted C16 was only checked at close. H20 (value and literature gate) was applied at the level of "timing", not at the level of each planned finding.
2. **Snippet exposure to the data-source paper.** Web searches in the novelty check returned aggregate results of Colgan 2026 (about 70 heritable programmes; A-P heritability; lineage and position jointly set fate). No B or C numbers were seen. Searches were then restricted (cell.com excluded).
3. **B's usable size was found at the confirmation step.** C14-S5 had already noted that "B = one E9.0 embryo", yet S4a computed power for a B look and Bence was asked to spend it. The oracle's n >= 2 rule should have been checked at S4a.
4. **C16-S1 first ran serially on one core** (about 3 h) before the parallel re-run; the run was cancelled unread.
5. **Smoke thresholds were loosened four times** (S1, S2, S3, S3c). Each was before real data and logged, but synthetic designs keep underestimating real noise.

## Lessons, each landed
| # | Lesson | Landing |
|---|---|---|
| 1 | At chapter opening, run the novelty search per planned finding (each S-step's expected result), not per chapter topic, and exclude the data-source paper's results pages from searches while its partitions are sealed | -> practice line (program.md checklist, chapter opening); raised to **H25** 2026-11-18 (Bence: every new chapter and hypothesis; commit hook enforces) |
| 2 | Any power calculation for a sealed look first checks the oracle's structural rule (usable units >= 2 per partition, units that can carry the statistic) | -> practice line (program.md checklist, before power) |
| 3 | Snippet exposure from searches is recorded in the novelty file and in any later use of that partition | -> practice line (merged into 1) |
| 4 | Fork pool inside each Actions job for independent fits | -> memory (done 2026-11-17, feedback_use_github_actions) |
| 5 | Synthetic smoke data must mimic real noise levels; size the threshold from a pilot null on train shuffles, not a fixed number | -> not adopted as new: the SE-scaled limits used in S3c-a1 already do this; keep using them |
